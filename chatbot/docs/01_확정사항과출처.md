**주의:** 제공된 루트 `AGENTS.md`의 '3영역' 설명은 구시점 자료. 실제 GitHub에는 `chatbot/`이 이미 있으므로 이를 삭제·통합하지 않는다. **ERD v4.1 SQL은 논리 스키마 확인 자료**로 사용한다. 백틱과 `COMMENT` 등 DDL 문법은 Oracle 실행용으로 변환·검증 없이 그대로 실행하지 않는다.

## C. 확정/제안 상태
- 확정: `chatbot/` 독립 FastAPI; Ollama의 로컬 Gemma 3 4B; LangChain 도입; Elasticsearch 세법 인덱스; Calc↔Chatbot 직접 연결 없음; Oracle 조회·저장은 Spring Boot; AI 전 기능의 backend/frontend 통합은 같은 기능 담당자 수행.
- 사용자 선택: 독립 '적용 세법 설명 카드'를 만들지 않고, 세법 설명은 챗봇 질의응답에 통합.
- 내부 API **소유자 제안:** `POST /internal/chat-responses`, `POST /internal/recommendations`, `X-Chatbot-Token` (상세는 03 문서). 팀 공통 API PDF에는 이 내부 경로가 없음. 네가 채택·공유 후 구현할 규칙이다.
- 미결정/검증: 최신 기준 브랜치, Security의 실제 세션/토큰 방식, 최초 안내 생성 시 동기/비동기 정책, 법령의 특정 귀속연도 적용 여부, Elasticsearch 서버 접근정보/인증/한글 분석기, 성능·동시성, 과거 답변 출처 영구저장 여부.

## E. 2026-11-09 팀 API 합의 반영
- 공식 PDF 2쪽: 성공/실패 응답 모두 `{success,data,meta,error}`로 감싼다. 목록에만 `PageMeta(page,size,total,totalPages)`가 있을 수 있다.
- 공식 PDF 3쪽: **내부 Calc/Chatbot FastAPI API는 봉투 사용하지 않음**. Spring이 변환해 React에 보낸다.
- 공식 PDF 3쪽: 500·503 `error.errorId`는 `GlobalExceptionHandler`가 만들며 같은 번호를 안전한 서버 로그에 남긴다. 415 `UNSUPPORTED_MEDIA_TYPE` 추가. 504 정책은 미기재.
- 프론트는 공통 `apiRequest()` 언래핑 여부를 실제 파일에서 확인한다.
- 팀 참고 저장소 `sjlimiei26/final_project_sample`은 코드 패턴 참고용이며, 최신 희망환급 공통 규칙과 현재 코드가 우선한다.
