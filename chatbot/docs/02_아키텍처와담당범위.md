# 02. 아키텍처와 기능별 책임

```text
사용자 브라우저
  └─ React Frontend
      └─ Spring Boot Backend :8080  ←→ Oracle (회원·결과·대화 저장)
          ├─ Calc FastAPI :8000      (세액 계산/판정; 별도 팀원)
          └─ Chatbot FastAPI :8001   (LangChain RAG + 모델 생성; 내가 담당)
              ├─ Elasticsearch :9200 (세법 조문 색인)
              └─ Ollama :11434 → Gemma 3 4B (로컬 모델)
```

- `Calc`와 `Chatbot`은 직접 HTTP를 주고받지 않는다. Calc 결과는 Spring Boot가 Oracle에 저장하고, Chatbot 요청 때 소유권 확인 후 읽어 전달한다.
- `chatbot/`에는 Oracle 연결·회원 인증 재구현·세액 재계산 로직을 두지 않는다.
- React에서 AI FastAPI·Ollama·Elasticsearch에 직접 연결하지 않는다.
- RAG의 법률 PDF/색인은 회원 데이터가 아니며, Elasticsearch에 사용자 질문·소득·카드내역을 색인하지 않는다.

## 담당 범위: 'AI 기능 전체' 한 사람이 구현
| 영역 | 네가 구현할 내용 | 건드리지 말 것 |
|---|---|---|
| `chatbot/` | LangChain `ChatOllama`, 프롬프트, PDF 전처리/색인, 검색, 두 내부 API, 서비스 토큰 검증, pytest | Calc 코드·Oracle 연결 |
| `backend/src/main/java/com/hoperefund/chat/` (예정) | 사용자용 Controller/Service/Mapper/DTO, ChatbotClient, 대화방 소유권 검증, PREDICTION 소유권·최소값 조회, RECOMMENDATION·CHAT_MESSAGE 저장, 오류 매핑 | 다른 기능의 DB 구조 임의 변경 |
| `backend/src/main/resources/mapper/` | Chat 전용 XML Mapper | 기존 Mapper 무단 수정 |
| `backend/src/main/resources/application.yml` | 이미 있는 chatbot URL·token·timeout 설정을 호출 코드와 연결 | 시크릿 하드코딩 |
| `backend/src/main/java/com/hoperefund/common/` | Spring Security/공통 예외에 필요한 **최소 통합** (현재 실제 코드/담당 영역 검토) | 다른 회원·관리자 권한 정책 무단 변경 |
| `frontend/src/pages/chatbot/ChatPanel.jsx`, `ChatbotPage.jsx`, `frontend/src/api/services.js` | 체험 응답→Backend 호출, 로딩/오류/이력/출처 표시, 기존 UI 유지 | 대시보드/시뮬레이션 UI 재제작 |
| 개발 문서 | AGENTS 보완, API 명세, 작업/테스트 기록 | 팀 합의 없는 공통 계약 변경 |

## 요청 흐름: 상담
1. React → `POST /api/chat-sessions/{sessionId}/messages` (`content` 본문, 팀 PDF 기준).
2. Spring Boot 인증 회원 확인, 세션 조회에서 `SESSION_ID`와 `MEMBER_ID`를 함께 조건으로 검사.
3. 연결된 `PREDICTION_ID`의 `MEMBER_ID` 소유권을 다시 검사. 필요 계산값·관련 공제 항목·검증된 `SOURCE_NOTE`, 최근 같은 세션의 메시지만 구성.
4. Spring Boot의 ChatbotClient → 내부 FastAPI 요청(서비스 토큰, 시간 제한, 최소 정보).
5. FastAPI 토큰 확인·Pydantic 검증 → Elasticsearch 법령 검색 → LangChain 프롬프트 + `ChatOllama` 응답 생성.
6. FastAPI → `{answer, model, sources}` 반환. `sources`는 반드시 실제 검색 결과 메타데이터에서 생성.
7. Spring Boot가 USER/AI 메시지를 Oracle에 저장하고 기존 팀의 사용자용 응답 반환. **LLM 추론 동안 DB 트랜잭션 유지 금지**.
8. React가 AI 답변 표시. 이전 대화는 Spring Boot 재조회. 메시지는 `MESSAGE_ID` 순서.

## 요청 흐름: 첫 절세 안내
1. Calc 계산 완료 → Spring Boot에서 `PREDICTION` 등 **저장 완료**.
2. Chatbot 내부 recommendation 생성 호출 (동기/비동기 재시도 정책 결정 필요).
3. 규칙 기반 수치 결과를 근거로 LLM이 안내 문구 생성; LLM이 `SAVING_AMOUNT`를 임의 계산하지 않음.
4. 성공하면 Spring Boot가 `RECOMMENDATION` 저장, 실패해도 원본 계산 결과는 보존.

## 보안 경계
- 로그인 인증/본인 데이터 권한: **Spring Boot**.
- Spring Boot→AI 서비스 인증: **FastAPI의 공유 토큰 검증** 및 접근 가능한 네트워크 제한.
- 개발용 `X-Member-Id`는 운영 인증 아님. 실제 Spring Security 연결 시 중단.
- Ollama, Elasticsearch 포트는 외부 브라우저에 공개하지 않음.
