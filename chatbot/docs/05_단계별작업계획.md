# 05. Codex 단계별 작업 계획 (기능 전체 소유)

> 코드는 **해당 단계만** 구현. 매 단계 보고서에 수정 파일, 실행 명령, 테스트 결과, 미구현 범위, 다음 위험을 적는다. 기능별 개발 담당자이므로 backend/frontend 작업도 이 계획의 범위에 포함.

| 순서 | 업무·코드 위치 | 완료 기준 | 아직 하지 않을 것 |
|---|---|---|---|

## 개인 개발 및 팀 통합 체크
- [ ] 로컬 작업 루트가 `C:\workspace\OllamaChatbot`인지 확인
- [ ] `git remote -v`에서 origin = 개인 저장소 확인
- [ ] 개인 저장소에서 기능별 커밋 및 테스트, 원격 전송 전 사용자가 승인
- [ ] 기능 완료 시 팀 최신 기준 `feature/chatbot`에서 관련 변경분 선별 반영
- [ ] 팀 `develop` PR에서 다른 팀원 변경과 충돌/회귀 검사, 최종 `main`은 팀 합의에 따름
- [ ] `.git`, `.metadata`, 비밀 `.env`, `.venv`, `node_modules` 등 로컬·비밀 파일을 이관하지 않음

## 세부 체크: 첫 절세 안내
- [ ] `PREDICTION`/DETAIL/INPUT DB 커밋 후 생성 요청
- [ ] 생성 실패해도 계산 저장 롤백하지 않음
- [ ] 중복 호출/재시도 시 `RECOMMENDATION` 중복 저장 정책 정의
- [ ] `SAVING_AMOUNT`와 관련 `TYPE_ID`는 Backend에서 검증 및 연결
- [ ] `GET /api/recommendations/{predictionId}`에 올바른 권한 확인

## 세부 체크: 상담 채팅
- [ ] 세션 소유권: `SESSION_ID` + 인증 회원의 `MEMBER_ID`
- [ ] 세션의 PREDICTION 소유권 재검증
- [ ] 질문 길이·민감정보·요청 빈도 검증
- [ ] 실패 시 AI 답변 행 저장 금지, USER 질문 저장 정책은 팀 기능명세와 맞춤
- [ ] `CHAT_MESSAGE`는 `MESSAGE_ID`로 정렬
- [ ] 기존 UI 체험 메시지와 실제 Oracle 메시지를 혼동하지 않음

## 통합 시 생길 수 있는 공통 영역 충돌
- Security 미구현/변경 중: 챗봇용 로직이 다른 API의 인증을 우회하게 하지 않음.
- Backend API 공통 경로가 아직 개발 중일 수 있음: 현행 Git 상태 확인 후 최소 변경.
- React는 계산 결과·사용자 세션의 현재 상태와 연결해야 하므로 기존 `aiService.reply` 교체 범위를 검증.

## 1단계씩 맡기는 이유
전체를 한 번에 구현하면 에러 원인이 Ollama·ES·FastAPI·DB·인증·브라우저 중 어디인지 알 수 없다. 단계별 작동하는 수직 단위를 확장한다.
