# 06. 로컬 실행 환경·환경변수·검증 방법

## 현재 GitHub 초기 상태(확인 당시)
- `chatbot/requirements.txt`: `fastapi`, `uvicorn[standard]`, `pydantic`.
- `chatbot/requirements-dev.txt`: `-r requirements.txt`, `pytest`, `httpx`, `ruff`.
- `chatbot/app/main.py`는 `health_router`만 등록, `/health`는 `{"status":"OK"}`.
- `chatbot/.env.example`에 `CHATBOT_HOST`, `CHATBOT_PORT=8001`, `CHATBOT_API_TOKEN`, `OLLAMA_BASE_URL=http://localhost:11434`, `OLLAMA_MODEL=gemma3`가 있음.
- Backend `application.yml`: `chatbot.base-url=http://localhost:8001`, `api-token`, `connect-timeout:3s`, `read-timeout:60s`.
- **현재 저장소의 실제 개발 상태는 작업 시작 시 다시 점검**.

## Windows + VS Code/Codex 준비
```powershell
# 이미 Clone한 개인 저장소를 개발 대상으로 사용
cd C:\workspace\OllamaChatbot

git status
git remote -v  # origin: uio6236/OllamaChatbot 확인
git branch -a
# 개인 저장소 main에서 개발해도 되며, 원하면 개인 개발 브랜치 추가 가능
# git switch -c dev/chatbot-rag
# 팀 저장소 feature/chatbot 브랜치는 기능 완료 후 별도로 사용

cd chatbot
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest -v
python -m ruff check .
python -m ruff format --check .
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```
- PowerShell 정책으로 활성화 실패 시 CMD `\.venv\Scripts\activate.bat` 사용하거나 `.venv\Scripts\python.exe` 직접 실행.
- `http://127.0.0.1:8001/health` → `{"status":"OK"}` 확인.

> 개인 저장소 `OllamaChatbot`에 팀 초기 소스가 복사되고 `chatbot/` 폴더가 있는 상태를 전제로 한다. 파일 복사는 `docs/08_개인저장소_Git운영.md` 참고. 팀 원본 `C:\workspace\two-trillion`에서 개발하지 않는다.

## Ollama 테스트
```powershell
ollama --version
ollama list
ollama run gemma3:4b
```
- Ollama 프로그램 실행 및 모델 사전 다운로드가 필요. 연결 주소는 개발 PC 로컬 기준 `127.0.0.1:11434`.
- 최초 LangChain 단계에서 `langchain-ollama` 설치, 정상 동작 후 의존성 버전 잠금·기록. ES·PDF 의존성도 해당 단계에서 추가.
- 기존 `OLLAMA_MODEL=gemma3` 값이 실제 설치 모델 `gemma3:4b`와 다른 경우 정확한 태그로 맞춤.

## 환경변수 예시 (실제 토큰 넣지 않음)
```dotenv
CHATBOT_HOST=127.0.0.1
CHATBOT_PORT=8001
CHATBOT_API_TOKEN=<set-in-local-env-only>
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=gemma3:4b
# 새로 합의할 항목 예시: ELASTICSEARCH_URL, ELASTICSEARCH_API_KEY, LAW_INDEX_NAME
```
- `CHATBOT_API_TOKEN`은 기존 `.env.example`의 이름을 그대로 사용. Python에서 `.env` 자동 로드 여부는 **현재 미구현**이므로 `python-dotenv`나 Pydantic Settings 연동을 구현하거나 OS 환경변수로 설정해야 한다.
- `.env`, DB 비밀번호, API 비밀키, 원시 사용자 질문/소득/카드 데이터, 실제 토큰을 Git 커밋·로그에 넣지 않는다.
- `langchain-ollama` 또는 타 라이브러리는 프로젝트의 Python 3.11.9와 호환되는 버전으로 검증 후 고정.

## 여러 서버 실행 시
| 서비스 | 기본 포트(개발) | 접근 |
|---|---|---|
| React Vite | 5173 | 브라우저 → Backend |
| Spring Boot | 8080 | 유저 API 제공·DB 저장 |
| Calc FastAPI | 8000 | Backend에서만 |
| Chatbot FastAPI | 8001 | Backend에서만 |
| Ollama | 11434 | Chatbot에서만, loopback 권장 |
| Elasticsearch | 9200 | Chatbot에서만, 인증·접근 제어 |
| Oracle | 1521 (일반 예시) | Backend, Calc의 허용된 계정 |

같은 PC라면 Chatbot/Ollama는 loopback. 다른 PC에서 실행하면 **localhost로는 연결할 수 없고** 내망 IP·방화벽·내부 인증·필요시 TLS 설정이 필요하다.

## 단계별 검증 명령
- `chatbot/`: `python -m ruff check .`, `python -m ruff format --check .`, `python -m pytest -v`.
- `backend/` (Windows): `mvnw.cmd spotless:check`, `mvnw.cmd -B verify` (프로젝트 설정 확인).
- `frontend/`: `npm run lint`, `npm test`, `npm run build` (실제 package scripts 확인).
- 단위 테스트는 Ollama/Elasticsearch가 없어도 mock/fake로 통과하게 하고, 연결 통합테스트는 별도 표시.

## 장애와 자원
- 모델 추론 중 Oracle 트랜잭션을 열어두지 않는다.
- 기존 Backend timeout 60초는 초기값이며 정확도·동시성·GPU 메모리 부담을 실제 시연 PC에서 측정.
- GPU 12GB / RAM 16GB 환경에서 Ollama+Elasticsearch+Spring+Calc+Vite 동시 실행 부하 테스트.
