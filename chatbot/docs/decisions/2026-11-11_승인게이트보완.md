# review-policy-v3 영역별 승인 게이트

## 구현과 신뢰 경계

실제 법령 조사·승인은 수행하지 않았다. 기존 v2 원장 3,133개 HOLD와 PDF/청크/manifest는 그대로 유지한다.
새 대기열은 ReviewRecordV3의 `initial-hold` 대상을 생성하지만 승인·영역을 자동 부여하지 않는다.
v2는 기존 ReviewRecord로 읽고 보존하며 운영 `approve_chunk`는 POLICY_VERSION_MISMATCH로 제외한다.
`validate_legacy_chunk`는 기존 비교표 정책의 회귀 확인 전용이며 운영 내보내기는 호출하지 않는다.

## 영역과 독립 이력

v3 원장은 `(chunkId, approvalTargetId)`별 sequence/previousReviewId 연쇄를 관리한다.
같은 청크의 서로 다른 대상은 독립 승인·회수할 수 있다. target ID는 검토자가 정하는 안정된 식별자다.
각 대상은 주 RULE 영역과 여러 필수 문맥 영역을 가진다. 다른 청크·문서의 문맥도 참조할 수 있다.
대상 전체에 대한 검토자 승인으로 문맥 영역을 함께 승인하며, 다른 대상의 승인을 자동 상속하지 않는다.
한 대상 회수는 다른 독립 대상을 자동 회수하지 않는다. 동일 법령의 변경 시 관련 대상도 별도로 재검토한다.

Region 필드: regionId, chunkId(전체 ID), documentVersion, contentHash, configHash,
lineIds, startOffset, endOffset, textHash, locator, officialLawId, officialLawVersion, role.
role은 RULE/PARENT/EXCEPTION/DEFINITION/APPLICATION이다.
줄은 원본 순서의 연속 영역이어야 한다. 줄 결합 원문에서 Python 유니코드 문자 기준 [startOffset,endOffset)을 선택한다.
종료 위치 null은 줄 결합 전체 끝이다. 범위 밖·빈 선택·중복/없는 줄·원문/설정/영역 해시 변경은 차단한다.
여러 비연속 영역은 별도의 Region으로 지정한다. 출력의 sourceSpans는 경계 검증용 원본 줄이며
실제 사용 텍스트는 각 Region.content와 offset이다. sourceSpans 전체를 답변 문맥으로 사용하지 않는다.

## 조건과 문맥

legalConditions는 kind/text/regionId/reviewed를 가진다. 조건 원문이 지정된 출력 영역 안에 정확히 있어야 한다.
unresolvedIssues가 있거나 기존 applicability.conditions 자유문자열이 남으면 차단한다.
기존 조건을 자동 분류하거나 삭제해 승격하지 않는다. 미검증 상태는 null/false를 유지한다.
필수 Region ID 전체와 실제 영역 집합이 같아야 하며, contextReviewed와 contextReviewNote 및 수동 구조 검토가 필요하다.
검토자는 상위 문장·단서·예외·정의·적용례의 완전성을 확인한다. 도구는 지정 목록 누락과 무결성을 검사할 뿐
누락된 법적 관계를 모두 발견하거나 개인의 공제 자격을 판단하지 않는다.
조건 원문이 잘려 나간 경우 차단하지만, 조건 목록 자체의 법적 완전성은 검토자가 확인한다.

## 공식 근거

EvidenceV3는 기존 URL/snapshotFile/snapshotHash/excerpt/locator/role/reviewed 외에
evidenceId, lawId, lawVersion, promulgationDate, effectiveDate, accessedAt, excerptHash, regionIds를 보존한다.
날짜는 ISO 날짜, 조회 시각은 시간대 포함 ISO datetime이다.
RULE과 APPLICATION 근거를 모두 요구하며, 각 출력 영역에 공식 발췌문이 정확히 대응해야 한다.
문맥 영역의 법령 ID/버전과 근거 ID/버전이 같아야 한다. 발췌문은 실제 UTF-8 스냅샷에 존재해야 한다.
공백 자동 보정도 하지 않는다. PDF 줄바꿈과 공식 문구가 다르면 승인하지 않고 원문 범위 재검토가 필요하다.
URL은 HTTPS law.go.kr/nts.go.kr 및 그 하위 도메인만 허용한다. 로컬 해시·도메인 검사는
실제 사이트에서 취득했다는 전자서명이 아니다. 자료 취득·버전·이용 조건 확인은 검토자 책임이다.
이번에는 공식 스냅샷이나 실제 승인 기록을 생성하지 않았다.

## 내보내기

`scripts/export_approved_chunks.py`의 기존 CLI 인자는 유지한다.
출력 스키마는 approved-context-v3이며 content 하나로 합치지 않고 regions[]에 원문·페이지·출처를 나누어 반환한다.
검색 어댑터는 묶음 전체와 legalConditions/requiredRegionIds를 보존해야 한다. 아직 검색 어댑터는 없다.
chunkId는 출력 payload의 결정적 해시이고, 각 영역은 원본 전체 chunkId를 유지한다.
입력 청크 수와 승인 대상 수를 별도로 보고한다. 동일 결과 폴더가 있으면 기존처럼 덮어쓰기를 거부한다.
원본/원장 변경은 해당 영역 사용을 차단하지만, 이미 배포된 색인 회수 동기화는 이후 Elasticsearch 범위다.

2025 안내서와 종전·개정 혼합 요약은 v3 운영 출력에서 보류한다. 좌동을 자동 해석하지 않는다.
현 단계의 핵심 법령 일부 영역 승인 기능은 LAW/DECREE/RULE 원문을 대상으로 한다.
과거 v2 비교표 선택 회귀 코드는 남겨 두되 실제 v3 승인으로 간주하지 않는다.
